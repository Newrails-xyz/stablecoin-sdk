# Development

This repo is an npm-workspaces monorepo; the published packages live under `packages/`.

## Quick start

```bash
npm install
npm run build     # tsc build for all packages
npm test          # vector consistency tests, etc. (vitest)
```

The ABI, deployment registry, and test vectors are plain committed source files, so day-to-day development is self-contained.

## Refreshing generated artifacts after a contract change

**Only after a contract change** do you refresh them by hand, in the upstream Foundry project:

```bash
# In the Foundry project: rebuild + regenerate the on-chain-verified vectors
forge build && forge test --match-contract SDKVectorsTest
```

Then in this repo:

- **ABI** — paste `forge inspect Stablecoin abi` output into `packages/contracts/src/abi.ts` (keep the `as const`).
- **Deployments** — edit `packages/contracts/src/deployments.ts` directly (single source of truth).
- **Vectors** — copy the Foundry project's `test-vectors/eip712-vectors.json` over `test-vectors/eip712-vectors.json` here.

Then `npm run build && npm test`.

## Test vectors

Every vector in `test-vectors/eip712-vectors.json` is generated by
`forge test --match-contract SDKVectorsTest`, and is verified by executing against the real contract before being written
(the domain matches the production Monad testnet deployment). The core package's `vectors.test.ts` requires the SDK to fully reproduce
each vector's digest and signature. After a contract or domain change, refresh the vectors as described above;
a failing SDK test signals a breaking change.
